# ETL Job Config App — Developer Guide

A beginner-friendly walkthrough of what this app does, how it is built, and how to keep developing it.

---

## What does this app do?

This is a **web form** that lets a signed-in user submit an ETL (Extract, Transform, Load) job configuration. The user fills in six fields — job name, data layer, source object, target object, load type, and watermark column — clicks **Submit**, and the app writes a new row into its own Rayfin database table called `EtlJobConfigIntake`.

A separate downstream Spark notebook (not part of this app) reads that table, picks up rows where `processed = false`, transfers them into the Lakehouse, and flips `processed` to `true`. The app never touches `processed` after insert — it only ever writes `false`.

## Architecture — how the pieces connect

Understanding the data flow from startup to a submitted form will help you know where to make any change.

### 1. Startup

```
index.html
  └─ src/main.tsx
       ├─ bootstrapAuth()          ← reads VITE_* env vars
       │    ├─ local URL?  → MockAuthService
       │    └─ remote URL? → RayfinAuthService
       └─ <AuthProvider authService={...}>
              └─ <App />
```

`bootstrapAuth()` (`services/bootstrap.ts`) is the decision point. It reads `VITE_RAYFIN_API_URL`. If that URL points at `localhost`, you get the mock auth (no Fabric needed, works fully offline). Any other URL switches to the real Fabric auth.

### 2. Auth guard

```
App.tsx  (BrowserRouter)
  ├─ /auth   → <AuthGuard requireAuth={false}> → <AuthPage />
  ├─ /       → <AuthGuard requireAuth={true}>  → <HomePage />
  └─ *       → redirect to /
```

`AuthGuard` reads `isAuthenticated` from the auth context. Unauthenticated users hitting `/` are bounced to `/auth`. Authenticated users hitting `/auth` are bounced to `/`.

### 3. Auth context

`hooks/AuthContext.tsx` is the single source of truth for auth state inside React.

```
AuthProvider
  state: user, loading, error
  actions: signIn(), signOut()

useAuth() hook — any component can call this to read state or trigger actions
```

Components never touch `IAuthService` directly; they go through `useAuth()`.

### 4. The form and database insert

```
HomePage.tsx
  ├─ form state: fields, errors, submitting, submitError, successResult
  ├─ validate()          ← client-side validation before any network call
  ├─ handleSubmit()
  │    └─ createJobConfig(fields)   ← api/jobConfig.ts
  └─ renders saved record or error block
```

`api/jobConfig.ts` calls `client.data.EtlJobConfigIntake.create(...)` on the Rayfin typed client. The client uses the session's publishable key and brokered auth — no Fabric API token needed. This works both locally (with `MockAuthService`) and in production.

### 5. The entity and database table

`rayfin/data/EtlJobConfigIntake.ts` defines the intake table using Rayfin decorators:

```
@entity()              ← tells Rayfin CLI to create a DB table
@authenticated('*')    ← signed-in users can read/write all rows

Fields
  id             UUID, auto-generated primary key
  jobName        text (max 200)
  layerName      text (max 50)    — staging | bronze | silver | gold
  sourceObject   text (max 500)
  targetObject   text (max 500)
  dataLoad       text (max 20)    — full | incremental
  watermarkColumn text (max 200)
  processed      boolean, default false   ← downstream notebook flips this
  submittedAt    datetime                 ← set to UTC now on every insert
```

`rayfin/data/schema.ts` registers the entity so the typed Rayfin client knows about it:
```typescript
export type BlankAppSchema = {
  EtlJobConfigIntake: EtlJobConfigIntake;
};
```

This is what makes `client.data.EtlJobConfigIntake` type-safe throughout the app.

### 6. Auth service implementations

Both services implement the same `IAuthService` interface:

| Method | MockAuthService (local) | RayfinAuthService (prod) |
|---|---|---|
| `signIn()` | Signs in with hardcoded `dev@contoso.com` | Opens Fabric/Entra broker popup |
| `signOut()` | Clears local session | Clears Fabric session |
| `getCurrentUser()` | Returns session user | Returns session user |
| `initEmbeddedAuth()` | Returns `null` (no iframe) | Tries silent iframe auth |

Because both implement `IAuthService`, the rest of the app is completely unaware of which one is running.

## Environment variables

Two files control environment variables. Never mix them up.

### `.env` — committed, currently empty

The pipeline-trigger IDs that used to live here have been removed. The file is kept as a placeholder — add project-specific non-secret values here if needed in the future.

### `.env.local` — auto-generated, never commit

Generated by `rayfin env --framework vite` (runs automatically before `npm run dev`):

```
VITE_RAYFIN_API_URL=https://...         # URL to your deployed Rayfin backend
VITE_RAYFIN_PUBLISHABLE_KEY=pk-...      # Client-safe publishable key
VITE_FABRIC_ITEM_ID=...                 # Rayfin backend item ID
VITE_FABRIC_WORKSPACE_ID=...            # Your Fabric workspace (used for auth)
VITE_FABRIC_TENANT_ID=...               # Entra tenant
VITE_FABRIC_PORTAL_URL=https://app.fabric.microsoft.com
```

## `rayfin/rayfin.yml` — what Rayfin services are on

```yaml
services:
  auth:          enabled: true    # Handles user sessions
  data:          enabled: true    # MSSQL database — hosts the EtlJobConfigIntake table
  staticHosting: enabled: true    # Serves the built React app at a Fabric URL
  storage:       enabled: false
  functions:     enabled: false
```

The `data` service uses MSSQL dialect. All entity tables are created and migrated automatically when you run `rayfin up`.

## How to run the app locally

### Prerequisites

- Node.js 18+
- Rayfin CLI installed (`npm install -g @microsoft/rayfin-cli`)
- Logged into Rayfin (`rayfin login`)

### Start the dev server

```bash
npm run dev
```

This does two things automatically:
1. Runs `rayfin up --exclude-services staticHosting` to start local backend services (auth, data) and apply the DB schema
2. Starts the Vite dev server at `http://localhost:5173`

Because `.env.local` points at the deployed Fabric backend by default, **the app will use `RayfinAuthService`** and will require a real Fabric sign-in. For fully offline local development, temporarily override `VITE_RAYFIN_API_URL=http://localhost:5168` in `.env.local` — the app will switch to `MockAuthService` automatically. Note: `createJobConfig` still calls the Rayfin database, so the local MSSQL service must be running for form submissions to work.

### Run tests

```bash
npm run test
```

### Build for production

```bash
npm run build
```

### Deploy to Fabric

```bash
npm run rayfin:up
```

## How to continue developing

### Adding a new form field

1. Add the field name and type to `FormFields` in `src/pages/HomePage.tsx`
2. Add it to `EMPTY_FORM` with its default value
3. Add a validation rule in `validate()`
4. Add a `<TextField>` or `<SelectField>` in the JSX grid
5. Add the field to `JobConfigInput` in `src/api/jobConfig.ts` and pass it to the `create()` call
6. Add the field to `EtlJobConfigIntake` in `rayfin/data/EtlJobConfigIntake.ts` with the correct decorator — use `@text({ max: N })` for MSSQL (never omit `max` or the GraphQL schema generation will fail at deploy time)
7. Re-run `npm run dev` so Rayfin migrates the table

### Adding a new page

1. Create `src/pages/YourPage.tsx`
2. Add a `<Route>` in `src/App.tsx` wrapped in `<AuthGuard requireAuth={true}>` if it requires login
3. Link to it from wherever makes sense (navbar, button, etc.)

### Adding reusable components

Put them in `src/components/`. Keep each component focused on one thing. The `TextField` and `SelectField` in `HomePage.tsx` are good examples — they handle their own label, input, and error display, and are defined at module scope (not inside the render function).

### Adding a custom React hook

Put it in `src/hooks/`. Hooks are functions that start with `use` and can call other hooks. `useAuth()` in `AuthContext.tsx` is the pattern to follow.

### Adding a new database table

1. Create `rayfin/data/YourEntity.ts` with `@entity()`, `@authenticated(...)`, and field decorators
2. Import the class in `rayfin/data/schema.ts`, add it to `BlankAppSchema`, and add it to the `schema` array
3. Use `.js` extension on the import path within `rayfin/data/` (required for the nodenext compiler)
4. Re-run `npm run dev` — Rayfin will create the table automatically

### Adding a new API call to the database

Add a function to `src/api/jobConfig.ts` (or a new file under `src/api/`) following the same pattern as `createJobConfig`: get the client via `getRayfinClient()`, call `client.data.YourEntity.create(...)` (or `.findMany()`, `.update()`, etc.), and return the result.

### Writing tests

Add test files to `src/__tests__/`. Follow the pattern in `AuthProvider.test.tsx`:
- Create a stub/mock of any service interface
- Render the component with Testing Library's `render()`
- Use `screen` queries to find elements
- Use `waitFor` for async state changes

## Common mistakes to avoid

| Mistake | What happens | Fix |
|---|---|---|
| Omitting `max` from `@text()` on MSSQL | `NVARCHAR(MAX)` column breaks GraphQL schema generation at deploy time | Always specify `@text({ max: N })` for every text field |
| Defining `TextField`/`SelectField` inside the page render function | React remounts the input on every keystroke, losing focus | Define sub-components at module scope (top of file) |
| Adding a new entity field without re-running `npm run dev` | The DB column doesn't exist yet, inserts fail at runtime | Always restart the dev stack after schema changes |
| Importing an auth service directly in a component | Tight coupling, harder to test | Use `useAuth()` instead |
| Committing `.env.local` | Leaks publishable keys and Fabric IDs | It is in `.gitignore` — leave it there |
| Calling `bootstrapAuth()` more than once | `initRayfinClient` throws because the singleton exists | Only call it in `main.tsx` |
| Forgetting `.js` extension on imports inside `rayfin/data/` | TypeScript (nodenext resolution) fails to resolve the file | Use `./EtlJobConfigIntake.js` even though the source is `.ts` |
